# 🏇 競馬予想AI (中央+地方)

netkeiba からレース結果を収集し、LightGBM で「3着以内(複勝圏)」と「1着(勝率)」を予想、
Harville 近似で馬連・ワイド・三連複の的中確率を見積もって買い目を提案するローカルツール。
単勝回収率のバックテスト機能付き。

## セットアップ

```powershell
cd 競馬予想
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

## 使い方

### 閲覧サイト (web/)

予想を「見る」ための画面。トップ(推奨レース)・予想(日別一覧)・結果(的中率と回収率)と、
レース詳細(出馬表・AI予想)がある。

```powershell
.venv\Scripts\python -m web.build     # 事前計算 (全レースをモデルに通す。約40秒)
.venv\Scripts\python -m web.export    # dist/ に静的ファイルを書き出す
.venv\Scripts\python -m web.server    # http://127.0.0.1:8000
```

`サイト起動.bat` をダブルクリックしてもよい。

画面側では推論しない。`web.build` が予想を `site_races` / `site_preds` に落とし、
`web.export` がそれを「1開催日 = 1 JSON」にまとめる。1日ぶん取れば
トップ・予想・結果・レース詳細が全部描けるので、画面遷移で取りに行かずに済む。
サーバは `dist/` をそのまま配るだけなので、手元で見えているものが本番と一致する。

モデルを学習し直したりデータを足したら `build` → `export` → `deploy` を流し直す。

### これからのレース (今週末など)

終わったレースは `web.build` が results から作る。これからのレースは
netkeiba の出馬表から作る。`web.build` は site_races を作り直すので、
必ず build のあとに実行する。

```powershell
.venv\Scripts\python -m web.upcoming 2026-11-14   # 日付を指定
.venv\Scripts\python -m web.upcoming --next       # 直近の開催日を探す
```

race_id の回・日目は日付から計算できないため、出馬表ページを探索して
見つける (1場あたり十数秒。1日3場見つかったら打ち切る)。
探索順は「過去の同じ月によく開催していた場」から。

オッズが出ていれば市場モデル、出ていなければ能力モデルを使う。
オッズが無い間は推奨レースと荒れ度が出せない (どちらも市場確率が要る)。

```powershell
# 中央競馬 2025年分を収集 (1〜2時間)
.venv\Scripts\python -m keiba.scraper jra 2025 2025

# 地方競馬を期間指定で収集 (場を絞ると速い: 44=大井 45=川崎 など)

# 血統 (父・母父) を収集 — 未取得の馬だけ。1頭=1秒

.venv\Scripts\python -m keiba.jvlink settings        # 利用キーの設定画面
.venv\Scripts\python -m keiba.jvlink race 2024-01-01  # 成績 (RA+SE)
.venv\Scripts\python -m keiba.jvlink horse 2024-01-01 # 馬マスタ/血統 (UM)

# 旧形式で取得したレースの通過順位・上り3Fを補完
.venv\Scripts\python -m keiba.scraper refresh

.venv\Scripts\python -m keiba.train

.venv\Scripts\python -m keiba.predict 202605030411

# 単勝回収率バックテスト
.venv\Scripts\python -m keiba.backtest --ev 1.2
```

## race_id の形式

- **中央**: `年(4) + 場(2) + 回(2) + 日目(2) + レース(2)` — 例 `202506050811` = 2025年 中山 5回8日目 11R
  - 場コード: 01札幌 02函館 03福島 04新潟 05東京 06中山 07中京 08京都 09阪神 10小倉
- **地方**: `年(4) + 場(2) + 月日(4) + レース(2)` — 例 `202544122911` = 2025年 大井 12/29 11R
  - 場コード: 30門別 35盛岡 36水沢 42浦和 43船橋 44大井 45川崎 46金沢 47笠松 48名古屋 50園田 51姫路 54高知 55佐賀 65帯広ば

## 仕組み

1. **収集** (`keiba/scraper.py`) — db.netkeiba.com のレース結果を SQLite (`data/keiba.db`) に保存。1秒/リクエストで負荷をかけない。取得済みレースはスキップされるので再実行で差分だけ取れる。血統は5代血統ページから父・母父を取得。
2. **特徴量** (`keiba/features.py`, 全40個) — 馬の過去成績(勝率・複勝率・近5走平均着順・休養日数)、**脚質**(近5走の初角通過順/頭数、上り3F平均)、**血統**(父・母父の産駒複勝率)、**コース攻略表** (`keiba/course_bias.py`: JRA全コースの枠・脚質バイアスと馬の適合度)、**コース構造の数値化** (`keiba/course_geo.py`: 回り方向・直線長・坂・洋芝 — 競馬辞典第12章準拠)、**適性**(同競馬場・同回り・同距離帯の複勝率)、**ペース圧**(逃げ・先行候補数×自馬脚質)、**ローテ**(距離変更幅・調子の傾き)、騎手の複勝率、斤量・馬体重・距離・馬場など。リーク防止のため各レースより前の情報のみ使用。
3. **学習** (`keiba/train.py`) — LightGBM 二値分類を2つ: 複勝圏(3着以内)モデルと勝率(1着)モデル。時系列80/20分割で検証。
4. **予想** (`keiba/predict.py`) — 出馬表を取得し複勝圏確率でランキング(◎○▲△)。勝率から Harville 近似で単勝・複勝・馬連・ワイド・三連複の的中確率を見積もり、買い目を提案 (`keiba/bets.py`)。オッズが取れた場合は単勝期待値(EV)も表示。「回収率が高い狙い目パターン」10種(東京芝1600の上がり最速差し馬など)に合致する馬には ★ が付く。予想は自動で履歴保存される。
5. **予想根拠の説明** (`keiba/explain.py`) — UI の予想結果で馬の行を選択すると、LightGBM 内蔵の SHAP 値で「どの特徴量が評価を押し上げた/下げたか」を表示。
6. **レース検索** (`keiba/racelist.py`) — 地方は日付+場から race_id を自動生成。中央は出馬表を探索して該当日の開催を発見(場ごとに数十秒)。
7. **予想履歴・結果照合** (`keiba/record.py`) — 保存した予想をレース後に結果と突き合わせ、◎の単勝/複勝的中率・回収率の実績を集計。
8. **バックテスト** (`keiba/backtest.py`) — 検証期間で「モデル本命の単勝」「期待値買い(予測勝率×オッズ≥閾値)」「1番人気(参考)」の回収率を比較。確定オッズ使用のためやや楽観的。

## 精度を上げるには

- データ量を増やす(最低でも1年分、できれば3年分以上)
- 血統収集と通過・上り補完を済ませてから学習する(未取得だと該当特徴量が欠損扱いになる)
- 予想したい対象(中央だけ/特定の地方場だけ)にデータを絞ってモデルを作る
- ※調教タイムは netkeiba の有料会員限定データのため対象外

## JRA-VAN Data Lab 連携 (中央の公式データ)

netkeiba の代わり/補完として、JRA公式の **JRA-VAN Data Lab** (月2,090円) から中央競馬の
成績・血統を取得できる。race_id は netkeiba と同一形式で保存されるため既存データと共存でき、
取得済みレースは netkeiba 側の収集でも自動スキップされる。

必要なもの:
1. **JRA-VAN Data Lab の契約** — https://jra-van.jp/dlb/ で申込み、利用キーを入手
2. **JV-Link** — Data Lab のソフトから導入 (インストール済みか確認: このPCは導入済み)
3. **32bit Python** — JV-Link が 32bit COM のため。python.org の Windows installer (32-bit) を
   インストールすれば自動検出される (`keiba/jvbridge.py` が 32bit 側で動き、DB に直接保存する)
4. UI「データ収集」タブの **JV-Link 設定** ボタンで利用キーを入力 → **成績を取得**

血統は netkeiba (血統登録番号) と JRA-VAN (繁殖登録番号) で ID 体系が違うため、
特徴量は **正規化した馬名** で突合している (`normalize_bloodline`)。

| タブ | できること |

| 🔮 レース予想 | 1レースの詳細予想。馬を選ぶとSHAPで根拠表示。買い目提案、オッズ再取得ボタン |
| 📒 予想履歴 | 保存した予想を結果と照合。◎の的中率・回収率の実績 |

| 📈 回収率検証 | 単勝バックテストに加え、**実際の配当を使った券種別回収率シミュレーション** |
| 🧠 学習 | 能力モデル/市場モデルの学習と確率校正 |
| 📥 データ収集 | netkeiba / JRA-VAN からの成績・血統・調教の取得 |

## モデル構成

競馬辞典 第12章 §3 に沿って2種類のモデルを持つ。

- **市場モデル** — オッズを特徴量に含む。**的中率重視** (検証: 複勝64.7% / 単勝31.2%)。予想の◎はこちら基準
- **能力モデル** — オッズを使わない純粋な能力評価。市場との差が「妙味」列になり、過小評価された穴馬を見つける

## 注意

- 予想は的中を保証しません。馬券購入は自己責任で。
- スクレイピングは netkeiba の個人利用の範囲で。`WAIT_SEC` を短くしないこと。
- 長時間連続でアクセスすると netkeiba 側にブロックされることがあります(空の 400 応答)。
  その場合は自動で中断されるので、数時間〜半日おいてから再開してください(取得済みデータは保持され、続きから再開されます)。
- 出走取消・除外馬は自動的に除外されます。
